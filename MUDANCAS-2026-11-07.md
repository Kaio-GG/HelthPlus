# Revisão de 07/11/2026 — correções, segurança, LGPD, auditoria e acessibilidade

## Para atualizar a sua máquina (5 minutos)

1. **Banco:** rode o `Api/database/schema.sql` de novo (Workbench: File > Open SQL Script > raio).
   Ele cria `log_auditoria` e `solicitacao_titular` e acrescenta as colunas novas. Não apaga nada.
2. **API:** `cd Api` e `npm install`. Confira se o `JWT_SECRET` do `Api/.env` tem 32+ caracteres
   (sem isso a API não sobe). Rode `npm test` — 10 testes, sem precisar do MySQL.
3. **App:** `cd app`, `npm install` e **`npx expo install expo-secure-store`**.
4. Todo mundo precisa entrar de novo no app uma vez (o formato do token mudou).
5. Pacientes que já tinham conta passam pela tela de **primeiro acesso** no próximo login.

## O que mudou

### Bugs corrigidos
- O app sempre abria pedindo login, mesmo com a sessão do nutricionista salva.
- `PUT /api/senha/:id` não exigia token: servia para testar senhas de qualquer conta.
- Código de redefinição de senha podia ser usado duas vezes (duas requisições juntas).
- Cadastro de nutricionista aceitava senha fraca (a API só checava o tamanho).
- Data de nascimento no futuro ou inexistente (30/02) era aceita — e ela forma a senha provisória.
- Texto maior que a coluna (nome, título de notificação, classificação) virava erro 500.
- Medidas absurdas (700 kg) entravam na avaliação.
- Senha atual errada na troca de senha passou a responder 400 (o 401 derrubava a sessão).
- Arquivo de PowerShell perdido na raiz e a pasta vazia `app/pages/Login` removidos.

### Segurança
- Cabeçalhos de segurança, CORS fechado, limite de 100 KB no corpo, erros sem stack trace.
- Limite de tentativas por IP/e-mail e bloqueio de 15 min após 5 senhas erradas.
- Token com algoritmo e emissor fixos; "versão da sessão" derruba tokens antigos ao trocar a senha.
- "Sair de todos os aparelhos" para os dois perfis.
- Sessão do app no cofre do celular (expo-secure-store); 401 leva de volta ao início com aviso.
- HTTPS opcional direto na API (`TLS_CERTIFICADO`/`TLS_CHAVE`) ou via proxy.
- Rotas de plano alimentar (sem tela) desligadas.

### LGPD
- Consentimento de verdade: tela de primeiro acesso com aceite explícito — do responsável, se menor.
- Senha provisória (data de nascimento) só serve uma vez; a troca é obrigatória.
- Direitos do titular no app: cópia dos dados, histórico de acessos, pedidos com prazo de 15 dias, revogação.
- Expurgo diário do que venceu (tokens, notificações lidas, telefone de consulta avulsa...).
- Política de privacidade reescrita com os itens do Art. 9º, versionada, sem afirmações falsas.
- Migração opcional para apagar as colunas de saúde órfãs: `Api/database/migracoes/001_minimizacao_lgpd.sql`.

### Auditoria
- `log_auditoria`: logins (inclusive falhos), fichas abertas, avaliações, exportações, aceites,
  acessos negados — sem nome nem dado de saúde, encadeado por hash.
- `npm run auditoria:verificar` confere se alguma linha foi editada ou apagada.
- Telas: "Histórico de acessos" (paciente e ficha) e "Privacidade e auditoria" (nutricionista).

### Acessibilidade
- Tela "Acessibilidade" (também antes do login): texto maior, alto contraste, reduzir animações.
- Paleta ajustada para contraste WCAG AA (botões e placeholders estavam reprovados).
- Leitor de tela: papéis, rótulos e estados nos componentes; erros anunciados; gráficos descritos em palavras.
